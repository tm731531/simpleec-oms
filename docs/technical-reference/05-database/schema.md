# Database Schema Reference

SimpleEC OMS uses PostgreSQL 16. All primary keys are `VARCHAR(20)` NanoID values generated by
application code using `IdGenerator.nextId()`. There are no `SERIAL` or `BIGSERIAL` columns.

**Source of truth**: `docker/init-db/01-schema.sql` (schema version v4, 2026-02-09)

---

## Detailed Table Definitions

### `platform_account`
Purpose: SimpleEC SaaS platform admin accounts. Independent of merchant tenants — used for
platform-level administration only.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | VARCHAR(20) | PK, NOT NULL | NanoID primary key |
| `name` | VARCHAR(50) | NOT NULL | Admin's display name |
| `email` | VARCHAR(256) | NOT NULL, UNIQUE | Login email |
| `password` | VARCHAR(512) | NOT NULL | Bcrypt-hashed password |
| `status` | VARCHAR(20) | NOT NULL, DEFAULT 'enable' | Account status: `enable`, `disable` |
| `created_at` | TIMESTAMPTZ | NOT NULL, DEFAULT now() | Record creation time |
| `updated_at` | TIMESTAMPTZ | NOT NULL, DEFAULT now() | Last update time |

Indexes:
- `platform_account_email` UNIQUE on `(email)`

- `idx_sellpack_merchant` on `(merchant_id)`

### `orders`
Purpose: Canonical order table. Every order from every platform is normalized and stored here.
PII fields (buyer name, phone, email, address) are encrypted at rest using AES-256-GCM.
`items` is stored as JSONB to avoid a separate order_items table.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | VARCHAR(20) | PK, NOT NULL | NanoID primary key (OMS order ID) |
| `merchant_id` | VARCHAR(20) | NOT NULL, FK → merchant.id | Owning merchant |
| `channel_id` | VARCHAR(20) | NOT NULL, FK → channel.id | Source channel |
| `channel_order_id` | VARCHAR(100) | NOT NULL | Platform's order ID (raw, e.g., Shopee's `order_sn`) |
| `channel_order_number` | VARCHAR(100) | | Platform's human-readable order number (e.g., Cyberbiz `#4319`) |
| `order_status` | VARCHAR(20) | NOT NULL, DEFAULT 'PENDING' | OMS unified status — see `OrderStatusEnum` |
| `buyer_name` | VARCHAR(512) | | **PII** — AES-256-GCM encrypted at rest |
| `buyer_phone` | VARCHAR(256) | | **PII** — AES-256-GCM encrypted at rest |
| `buyer_email` | VARCHAR(512) | | **PII** — AES-256-GCM encrypted at rest |
| `buyer_info` | JSONB | | Additional buyer metadata (not encrypted — no direct PII) |
| `shipping_address` | TEXT | | **PII** — AES-256-GCM encrypted at rest |
| `shipping_method` | VARCHAR(50) | | Shipping method code |
| `shipping_info` | JSONB | | Shipping metadata (tracking, estimated delivery, etc.) |
| `payment_method` | VARCHAR(50) | | Payment method (e.g., `credit_card`, `cod`, `transfer`) |
| `total_amount` | DECIMAL(12,2) | NOT NULL, DEFAULT 0 | Grand total (items + shipping - discount) |
| `shipping_fee` | DECIMAL(12,2) | NOT NULL, DEFAULT 0 | Shipping cost |
| `discount_amount` | DECIMAL(12,2) | NOT NULL, DEFAULT 0 | Total discount applied |
| `items` | JSONB | NOT NULL, DEFAULT '[]' | Order line items array (see structure below) |
| `is_rollback` | BOOLEAN | NOT NULL, DEFAULT false | `true` = historical backfill order |
| `refund_amount` | NUMERIC(15,2) | NOT NULL, DEFAULT 0 | Cumulative refund amount (updated on each refund) |
| `has_refund` | BOOLEAN | NOT NULL, DEFAULT false | Fast filter flag — `true` if any refund exists |
| `channel_created_at` | TIMESTAMPTZ | | Order creation time on the platform (used for stats attribution) |
| `paid_at` | TIMESTAMPTZ | | Payment confirmation time |
| `shipped_at` | TIMESTAMPTZ | | Shipment time |
| `created_at` | TIMESTAMPTZ | NOT NULL, DEFAULT now() | OMS record creation time |
| `updated_at` | TIMESTAMPTZ | NOT NULL, DEFAULT now() | Last update time |

**`items` JSONB structure** (array of order line items):
```json
[
  {
    "channelItemId":  "platform-specific-item-id",
    "productName":    "商品名稱",
    "sku":            "SKU-001",
    "quantity":       2,
    "unitPrice":      790.00,
    "totalPrice":     1580.00
  }
]
```

**`OrderStatusEnum` values** (unified across all platforms):
`pending` → `confirmed` → `ready_to_ship` → `shipping` → `shipped` → `completed` | `cancelled`

Indexes:
- `idx_order_channel_order` UNIQUE on `(channel_id, channel_order_id)` — upsert key
- `idx_order_merchant_status` on `(merchant_id, order_status)`
- `idx_order_created` on `(created_at DESC)` — for recent orders queries
- `idx_order_items` GIN on `(items)` — for JSONB containment queries
- `idx_order_stats` on `(merchant_id, channel_id, channel_created_at)` — for stats queries
- `idx_order_has_refund` PARTIAL on `(merchant_id, has_refund) WHERE has_refund = true`

### `daily_statistics`
Purpose: Pre-aggregated daily business metrics, partitioned by `stat_date` (monthly partitions).
This table is the source of data for dashboards and reports. Rows are upserted by
`DailyStatisticsService` using a Redis dirty-marker pattern.

**Composite PK**: `(id, stat_date)` — required by PostgreSQL declarative partitioning.
The logical unique key is `(merchant_id, platform_id, channel_id, stat_date)`.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | VARCHAR(20) | PK (part 1), NOT NULL | NanoID |
| `merchant_id` | VARCHAR(20) | NOT NULL, FK → merchant.id | Owning merchant |
| `platform_id` | VARCHAR(20) | NOT NULL, FK → platform.id | Platform |
| `channel_id` | VARCHAR(20) | NOT NULL, FK → channel.id | Channel |
| `stat_date` | DATE | PK (part 2), NOT NULL | Date of the statistics |
| `new_order_count` | INTEGER | DEFAULT 0 | **Business view**: orders created on this date (by `channel_created_at`) |
| `new_order_amount` | NUMERIC(15,2) | DEFAULT 0 | **Business view**: total amount of new orders |
| `gross_order_count` | INTEGER | DEFAULT 0 | **Revenue view**: orders excluding cancelled |
| `gross_amount` | NUMERIC(15,2) | DEFAULT 0 | **Revenue view**: total amount excluding cancelled |
| `received_count` | INTEGER | DEFAULT 0 | **Finance view**: orders in `confirmed` status or higher |
| `received_amount` | NUMERIC(15,2) | DEFAULT 0 | **Finance view**: total amount of received orders |
| `refund_count` | INTEGER | DEFAULT 0 | Number of refunds on this date |
| `refund_amount` | NUMERIC(15,2) | DEFAULT 0 | Total refund amount |
| `net_amount` | NUMERIC(15,2) | DEFAULT 0 | `received_amount - refund_amount` |
| `shipped_count` | INTEGER | DEFAULT 0 | **Logistics view**: orders shipped on this date |
| `completed_count` | INTEGER | DEFAULT 0 | Orders completed (delivered) |
| `cancelled_count` | INTEGER | DEFAULT 0 | Orders cancelled |
| `item_sold_count` | INTEGER | DEFAULT 0 | Total units sold |
| `created_at` | TIMESTAMPTZ | DEFAULT now() | Record creation time |
| `updated_at` | TIMESTAMPTZ | DEFAULT now() | Last update time |

Indexes:
- `idx_daily_stats_unique` UNIQUE on `(merchant_id, platform_id, channel_id, stat_date)`

**Partitions** (monthly, 2026):
`daily_statistics_2026_01` through `daily_statistics_2026_12`, plus `daily_statistics_default`
for data outside the explicit range.

### `failed_task_logs`
Purpose: Persistent store for Kafka dead-letter messages. Populated by `DltConsumer` when a
message reaches `task.dlt`. Used for manual investigation, replay, and auditing.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | VARCHAR(20) | PK, NOT NULL | NanoID primary key |
| `message_id` | VARCHAR(50) | | Kafka message key or request ID |
| `task_type` | VARCHAR(50) | | `header.taskType` from the failed message |
| `task_action` | VARCHAR(100) | | Sub-action within the task type |
| `source_job_type` | VARCHAR(50) | | Which service produced the message |
| `merchant_id` | VARCHAR(20) | | `header.merchantId` (for tenant-scoped queries) |
| `owner_id` | VARCHAR(50) | | Order ID or resource ID being processed |
| `original_topic` | VARCHAR(100) | | Kafka topic the message was originally published to |
| `original_key` | VARCHAR(200) | | Kafka partition key of the original message |
| `error_message` | TEXT | | Exception message or error description |
| `reason` | VARCHAR(50) | | Failure reason category: `UNSUPPORTED_VERSION`, `MALFORMED_MESSAGE`, `MAX_RETRIES`, etc. |
| `retry_count` | INTEGER | DEFAULT 0 | Number of retry attempts before DLT |
| `payload` | JSONB | | Full original message payload for replay |
| `created_at` | TIMESTAMPTZ | DEFAULT now() | When the DLT record was created |

Indexes:
- `idx_failed_task_created` on `(created_at)` — for time-range queries
- `idx_failed_task_action` on `(task_action)` — for filtering by task type
